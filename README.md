## Description

**Jigsaw Decryptor** is a *Windows Forms* application written in C# (.NET Framework 4.7.2) that disinfects a machine affected by the **Jigsaw** ransomware: it decrypts the hijacked files and removes every malware artifact, leaving the system as if the attack had never happened.

What the application does:

1. **Decrypts** the files encrypted by Jigsaw (`.fun` extension), restoring the original and deleting the encrypted copy.
2. **Terminates** the malware processes.
3. **Deletes** the files the malware dropped on the system.
4. **Removes the persistence** the malware created in the Windows registry.

Tested on the sample with SHA256: `3ae96f73d805e1d3995253db4d910300d8442ea603737a1428b613061e7f61e7`.

> **Limitation:** decryption relies on the static key and IV embedded in Jigsaw. Variants that use a different key cannot be decrypted with this tool.

> [!NOTE]
> Project developed during the Master's Thesis (TFM) **"Malware analysis of the Jigsaw ransomware"**.

## Architecture

A two-layer application with no external dependencies (only the .NET Framework base library):

```
Jigsaw-Decryptor/
├── Program.cs          Entry point: opens the main form
├── Form1.cs            UI: confirmation, progress and cleanup orchestration
├── Form1.Designer.cs   Form layout (generated by Visual Studio)
├── Resources/          Application logo
└── Utils/
    ├── Config.cs       Constants and paths of the malware artifacts
    ├── Decryptor.cs    AES decryption of the files
    ├── Cleaner.cs      Removal of processes, files and persistence
    └── Logger.cs       Activity log written to a file
```

Execution flow:

1. The user clicks **Decrypt My Files!** and confirms the warning.
2. `Decryptor` reads the list of encrypted files left by the malware (`%APPDATA%\System32Work\EncryptedFileList.txt`).
3. A `BackgroundWorker` decrypts each `<file>.fun` with AES-128 to its original path, without freezing the interface, and updates the progress bar.
4. When finished, `Cleaner`:
   - kills the malware's `drpbx.exe` and `firefox.exe` processes (matching the **full path**, so the legitimate Firefox is not affected);
   - deletes `%APPDATA%\System32Work`, `%LOCALAPPDATA%\Drpbx` and `%APPDATA%\Frfx`;
   - removes the `firefox.exe` value from `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`.
5. The application reports whether the removal was total or partial.

All operations are recorded with a timestamp in `log_<date>.txt`, in the executable's folder. This file shows whether any item could not be decrypted.

## Building

**Requirements:** Windows, Visual Studio 2022 (*.NET desktop development* workload) and the .NET Framework 4.7.2 Developer Pack.

### With Visual Studio

1. Open `Jigsaw-Decryptor.sln`.
2. Select the **Release** configuration (Any CPU).
3. Menu **Build → Build Solution** (`Ctrl+Shift+B`).
4. The executable is generated at `Jigsaw-Decryptor\bin\Release\Jigsaw-Decryptor.exe`.

### From the command line

In a *Developer Command Prompt for VS 2022*:

```
msbuild Jigsaw-Decryptor.sln /p:Configuration=Release
```

The output ends up in the same path: `Jigsaw-Decryptor\bin\Release\Jigsaw-Decryptor.exe`. The `.exe` is self-contained and needs no installation.

## Usage

1. Copy `Jigsaw-Decryptor.exe` to the infected machine.
2. Run it by **double-clicking**, logged in as the affected user (the malware works on their profile and registry).
3. Click **Decrypt My Files!** and accept the warning.
4. Wait for the progress bar to reach the end. You will see the file being decrypted at each moment.
5. When finished, the application shows whether the malware was removed **totally** or **partially** and closes itself.

Notes:

- Do not close the application while it is decrypting.
- If `EncryptedFileList.txt` is missing, the tool cannot know which files to decrypt and will close.
- If the removal was partial, check the `log_<date>.txt` file next to the executable to see what failed.
